4. PRERENDER / SSG PIPELINE (CRITICAL TO UNDERSTAND)
================================================================================

The site is a React SPA but every route ships as fully-rendered static HTML for
crawlers/instant paint:

  npm run build =
    1) vite build                → dist/ client bundle (hashed assets)
    2) vite build --ssr scripts/prerender-entry.jsx --outDir .prerender
                                 → SSR module bundle (excludes LeaveWarning)
    3) node scripts/prerender.mjs→ reads dist/index.html template, renders each
       route with renderToString + StaticRouter, replaces tokens, writes:
         dist/index.html, menu.html, about.html, contact.html, order.html,
         order/success.html, privacy.html, terms.html, 404.html (noindex)
         dist/robots.txt + dist/sitemap.xml (generated from SITEMAP_PATHS)

  Tokens replaced per route: %%RENDERED_BODY%% %%PAGE_TITLE%% %%DESCRIPTION%%
  %%ROBOTS%% %%CANONICAL%% %%OG_TITLE%% %%OG_DESCRIPTION%% %%OG_URL%%
  %%PAGE_PATH%% %%SITE_URL%% %%EXTRA_JSONLD%% (FAQPage schema injected on
  /about, built from content.en.faq.items so it can't drift from the UI).

Cloudflare Workers assets serving rules (why flat files work):
  - html_handling "auto-trailing-slash": /menu serves dist/menu.html
  - not_found_handling "404-page": any unknown path serves dist/404.html WITH
    HTTP STATUS 404 (verified live: status=404, 14.5KB styled body)

RULES FOR THIS PIPELINE (breaking these broke the build before):
  - Do NOT re-add React.lazy/Suspense around route components — they were
    removed deliberately because lazy() renders fallbacks during SSR.
  - Components must be SSR-safe: no window/document/localStorage/sessionStorage
    access during render. Use useState(() => typeof X === 'undefined') patterns
    and useEffect guards (Reveal, CartContext initCart, LocaleProvider
    initialLanguage, loadOrderDraft all do this correctly).
  - react-router v7: StaticRouter comes from 'react-router', NOT react-router-dom.
  - After building, .prerender/ is deleted by prerender.mjs and gitignored.

5. INTERNATIONALIZATION (EN/AR) — HOW IT WORKS
================================================================================

- src/utils/i18n.js exports `content` = { en: {...}, ar: {...} } — one big nested
  object of ALL copy (nav, home, order wizard steps, cart, cookie banner, FAQ,
  privacy, terms, notFound, success...). Adding copy means adding it in BOTH
  locales; missing keys crash components that destructure them.
- LocaleProvider stores language ('en'|'ar') in state, persists to localStorage,
  sets <html lang dir> (rtl for Arabic) via effect. useLocale() returns
  { c, language } where c = current locale's content object.
- Components grab section objects: const t = c.cart; const b = c.order.basics…
- Arabic typography handled by html[lang="ar"] CSS rules switching font-family
  to Cairo and zeroing negative letter-spacing.
- RTL layout: logical mirroring done explicitly in app.css via [dir="rtl"]
  selectors — CartDrawer slides from LEFT in Arabic (slideInLeft keyframes),
  header mobile nav opens from left, arrows flip via transform scaleX(-1).
- EVERYTHING user-facing must be translated. Historical bug: cart UI was
  hardcoded English — fixed by adding c.cart.* keys to both locales. If you add
  UI text, add i18n keys for both en and ar.

6. SECURITY POSTURE (DO NOT REGRESS)
================================================================================

public/_headers applies to all routes:
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src
    'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:;
    connect-src 'self'; frame-src https://www.google.com https://maps.google.com;
    media-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self';
    frame-ancestors 'none'; upgrade-insecure-requests
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  X-Content-Type-Options: nosniff | X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()
  Cross-Origin-Opener-Policy: same-origin
Cache rules: /assets/* and /fonts/* immutable 1yr; favicon/icons/og-image 7d;
robots/sitemap 1h.
Notes: style-src keeps 'unsafe-inline' because React inline styles need it;
script-src has NO unsafe-inline (JSON-LD blocks are exempt from CSP);
frame-src allows ONLY Google Maps iframe (contact page embed).

Verified behaviors (tested locally + live):
  - POST to any path → 405; unknown paths → styled 404 with HTTP 404;
    path traversal (/assets/../wrangler.jsonc) blocked; npm audit clean;
    no secrets in repo; WhatsApp URLs properly encoded; honeypot field
    (_website input) on contact form for bot filtering.

Security-sensitive code decisions:
  - Order reference numbers: crypto.getRandomValues(new Uint32Array(1)) —
    NEVER revert to Math.random().
  - sessionStorage 'standard_order_draft' holds only order-form fields (name/
    phone/email/city/address/notes/services/budget/date/time/consent). PII is
    session-scoped, acceptable; documented as accepted residual risk (S5/INFO).
  - No backend exists AT ALL. Nothing ever transmits except WhatsApp deep links.

7. UI/UX CONVENTIONS & KNOWN FIXES (WHY THINGS LOOK THE WAY THEY DO)
================================================================================

Accessibility/WCAG decisions:
  - Gold text on light backgrounds MUST be var(--gold-text) #7d6540 (≥4.5:1),
    NOT var(--gold)/--gold-dark which fail contrast (~1.9:1). Bright --gold is
    reserved for dark navy surfaces (.home-hero/.page-hero/.gallery-section/
    .cta-band/.success-page/.not-found .eyebrow overrides restore it there).
  - Other contrast fixes applied: order-step labels #6f6a5c, footer muted
    rgba(255,255,255,.58–.78), order-summary dt #6b6357, .text-link uses
    --gold-text (+ .gallery-heading override back to bright gold on navy).

Layout bug fixes baked in (do not undo):
  - Floating overlap: on ≤850px the FloatingCart moves up (bottom:88px,
    width:min(calc(100% - 32px),400px)) so it never covers the WhatsApp pill.
  - Equal-height grid cells: .service-grid > * and .occasion-grid > * are
    display:flex/flex-direction:column with .service-card/.occasion flex:1 —
    this is what keeps shared border lines even when sibling text lengths
    differ (was visibly broken on phones). Occasions become a gap-line 2×2
    grid under 800px (border:none !important on cells there is intentional).
  - Tablet breakpoint added @media (max-width:1080px): service/addon/package/
    menu grids drop to 2 columns; footer 2-col with brand spanning.
  - Menu page (MenuCatalog): centered SectionIntro, category chip nav
    (.menu-catalog__nav anchors to collection ids — camelCase keys like
    #streetFood), stretch equal-height cards, centered h3 with gold ::after
    rule, always-visible qty/add controls, scroll-margin-top:110px for sticky
    header offset. Style target: clean Amazon-like product listing.
  - About page: masonry tile border-radius normalized to uniform 16px (the
    random blob radii like '72px 12px 14px 46px' were removed on purpose),
    section paddings tightened (~86px vs 113px), story-grid gap clamped
    42–92px.
  - RTL mirrors drawers/nav explicitly (see section 5).

Images: brand logos compressed to ≤56px height PNGs (~106KB total, down from
1.1MB); photos are WebP q80 capped 1600px long edge (~1.8MB total). All imgs
have explicit width/height (CLS protection), loading=lazy below fold,
decoding=async. Home hero img: fetchPriority=high loading=eager.

Performance specifics:
  - Fonts fully self-hosted + preloaded (DMSans 400/700 latin, Playfair 700
    latin); fonts.css uses unicode-range subsets with font-display swap.
  - content-visibility:auto + contain-intrinsic-size on .about-gallery,
    .gallery-section, .occasion-section, .testimonial-section, .footer
    (with print override). Do not apply to .menu-catalog (anchor jumps).
  - JS bundle ~352KB raw/~120KB gzip single-chunk (lazy-loading was traded away
    for prerendering — accepted tradeoff). If bundle size becomes a problem,
    solve via manual vendor splitting, NOT React.lazy route suspension.
